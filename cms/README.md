# Редакционная система

Отдельное приложение на [Payload CMS](https://payloadcms.com) (Next.js + PostgreSQL). Здесь работает редакция:

- **Материалы** для сайта: новости, истории, карточки, тесты, подкасты. Есть черновики, автосохранение и история версий.
- **Задачи**: кто, что и к какому сроку делает; статусы «Новая → В работе → На проверке → Готово».
- **Сотрудники** с ролями и правами.
- **Посты для соцсетей**: Telegram, ВКонтакте и MAX. Отправка сразу или по расписанию.
- **Медиатека**: фотографии с подписью, автором и источником.

На главной панели каждый сотрудник видит свои открытые задачи и состояние подключений к соцсетям.

## Роли

| Что можно | Администратор | Редактор | Журналист | SMM |
|---|:-:|:-:|:-:|:-:|
| Заводить сотрудников, менять роли | ✓ | | | |
| Писать материалы (черновики) | ✓ | ✓ | только свои | |
| Публиковать и править опубликованное | ✓ | ✓ | | |
| Удалять материалы | ✓ | ✓ | | |
| Ставить задачи | ✓ | ✓ | ✓ | ✓ |
| Видеть задачи | все | все | свои и поставленные им | свои и поставленные им |
| Переназначать ответственного | ✓ | ✓ | | |
| Готовить и отправлять посты в соцсети | ✓ | ✓ | | ✓ |

Правила проверяются на сервере (`src/access/roles.ts`, хуки коллекций), а не только в интерфейсе. Их покрывают тесты в `tests/int/access.int.spec.ts`.

## Запуск на своём компьютере

Нужны Node.js 20+ и PostgreSQL. Проще всего поднять PostgreSQL через Docker.

```bash
cd cms
cp .env.example .env          # заполните PAYLOAD_SECRET и SEED_ADMIN_*
docker compose up -d db       # PostgreSQL на 127.0.0.1:5432
npm install
npm run seed                  # первый администратор из SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD
npm run dev                   # http://localhost:3000/admin
```

`npm run seed:demo` дополнительно создаёт трёх тестовых сотрудников (редактор, журналист, SMM) с тем же паролем, что у администратора. Он же переносит демо-материалы сайта с фотографиями и добавляет пример задачи и поста.

Проверки: `npm run lint`, `npx tsc --noEmit`, `npm test`. Тестам нужна отдельная база `newsroom_test`:

```bash
createdb -O payload newsroom_test
```

## Связь с сайтом

Сайт остаётся статическим на GitHub Pages. При публикации, правке или удалении опубликованного материала система просит GitHub Actions пересобрать сайт. Через 1–2 минуты изменения на сайте.

Чтобы это заработало, когда система будет на сервере:

1. В GitHub создайте fine-grained токен с доступом только к репозиторию сайта и правом **Contents: Read and write**. Пропишите его в `.env` системы как `GITHUB_TOKEN`, а `GITHUB_REPO=владелец/репозиторий`.
2. В репозитории сайта откройте **Settings → Secrets and variables → Actions → Variables** и добавьте переменную `CMS_URL` с публичным адресом системы, например `https://cms.example.ru`.

Без `CMS_URL` сайт собирается из демо-материалов (`src/lib/news.ts`), как сейчас.

На первый экран главной попадает материал с отметкой «Главная новость». Остальные места раскладываются по формату и свежести.

## Подключение соцсетей

Токены хранятся только в `.env` на сервере, в базу и в репозиторий не попадают. После заполнения перезапустите систему: на главной панели канал станет «подключён».

### Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен → `TELEGRAM_BOT_TOKEN`.
2. Добавьте бота администратором канала с правом публикации.
3. `TELEGRAM_CHAT_ID`: `@имя_канала` для публичного канала или числовой ID вида `-100…` для закрытого.

Пост с картинкой уходит как фото с подписью. Подпись ограничена 1024 знаками; если текст длиннее, уходит только текст.

### ВКонтакте

Публикация идёт методом `wall.post` от имени сообщества.

- `VK_GROUP_ID` — ID сообщества (без минуса).
- `VK_ACCESS_TOKEN` — ключ доступа **пользователя-администратора** сообщества с правом `wall`. Сейчас VK выдаёт право `wall` только по запросу в поддержку: devsupport@corp.vk.com ([документация метода](https://dev.vk.com/ru/method/wall.post)). Ключ сообщества для этого метода не подходит.

Ссылка на материал добавляется как сниппет. Загрузка картинок в VK пока не сделана.

### MAX

1. Создайте бота на [платформе MAX для партнёров](https://dev.max.ru/docs-api) (для этого нужен верифицированный профиль организации) и скопируйте токен → `MAX_BOT_TOKEN`.
2. Добавьте бота администратором канала и узнайте ID канала → `MAX_CHAT_ID`.
3. API MAX (`platform-api2.max.ru`) использует сертификат Минцифры. Скачайте корневой сертификат «Russian Trusted Root CA» и укажите путь к нему в `NODE_EXTRA_CA_CERTS`, иначе Node.js не установит соединение.

Пост уходит текстом с кнопкой «Читать на сайте». Загрузка картинок в MAX пока не сделана.

### Отправка

- Кнопка **«Отправить сейчас»** в карточке поста отправляет его во все выбранные каналы.
- Статус «Запланирован» плюс «Время отправки» — пост уйдёт сам: планировщик внутри системы проверяет очередь каждую минуту.
- Результат по каждому каналу (ссылка на пост или текст ошибки) виден в блоке «Отправки».
- Повторная отправка шлёт пост только туда, где была ошибка.

## Развёртывание на сервере

Когда выберете сервер:

```bash
cd cms
cp .env.example .env    # заполните все значения, NODE_ENV не нужен
docker compose --profile server up -d --build
```

Система слушает `127.0.0.1:3000`. Перед ней нужен reverse proxy с HTTPS (Caddy или nginx) и домен для `SERVER_URL`. Миграции базы применяются автоматически при старте. Загруженные файлы и база лежат в Docker-томах `media` и `pgdata`; их нужно включить в резервное копирование.

Если меняются коллекции, после правок создайте миграцию: `npm run payload migrate:create <название>`.
